## Request and acceptance criteria

Provide scoped MCP state and actual page operations alongside the VPN refactor,
with separate consent, source-generated schemas, cancellation and lifecycle
verification. No new tunnel/backend behavior and no live Windows UI automation.

## Implementation and decisions

Three tools read the active page, set its decorative-particle preference and
open its existing fixed Windows VPN settings action. Their typed contracts and
limits are in `Mcp/VPN.md`. The adapter takes an active-page resolver and a
session predicate. `McpAccessService.Start` gains optional final `IMcpVpnService?
vpn`; the parent wires it to the actual page. No private page instance is made.

VPN read/control grants are separately persisted, default false in older stored
consent, localized in Persian/English and discoverable through generated schemas.
Control-only operations receive no VPN readback, including accidentally returned
data from other domains. Caller/page/adapter cancellation and consent revocation
suppress stale results; failures are sanitized. The shared page is never disposed
by the adapter. No IP, credentials, SSID, local path or arbitrary URI is exposed.
