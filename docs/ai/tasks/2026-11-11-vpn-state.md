## Request and acceptance criteria

Replace decorative VPN telemetry with genuine bounded OS state, preserve the
decorative particle option without starting a pretend VPN connection, provide a
fixed Windows VPN settings action, honor reduced motion and release observers
when the cached page is inactive. Use the same state/actions from the page and MCP.

## Implementation and decisions

- `VPNPageViewModel` is a WinUI-independent, reflection-free .NET 11
  `INotifyPropertyChanged` state owner. VPN configured/connected stay false:
  no transport, profile manager or traffic measurement exists in this feature.
- `WindowsVpnPageEnvironment` observes `NetworkInformation.NetworkStatusChanged`
  and `UISettings.AnimationsEnabledChanged` only during the active page lifetime.
  Network enumeration runs off the UI thread. Dispatcher work is coalesced;
  an in-flight snapshot is refreshed once more if a change arrived during it.
  Generation checks discard results from earlier page lifetimes. There is no polling.
- Only `internet`, `local`, `offline`, or `unknown` leave the platform boundary.
  Adapter names, addresses, SSIDs and credentials are not exposed.
- The particle preference uses the app's existing
  `Microsoft.Windows.Storage.ApplicationData.GetDefault().LocalSettings` policy
  under `Vpn.ParticlesEnabled`. Failed persistence preserves the live choice and
  reports a sanitized error; choosing the same value can retry the save.
- The sole external action opens the fixed `ms-settings:network-vpn` URI. It has
  one busy request, a 15-second deadline, caller/page cancellation, sanitized
  errors and a stale-completion guard. Caller cancellation propagates to the MCP
  boundary. Page deactivation cancels the action and returns false. A successful
  launch means Windows accepted the URI, not that a VPN connection was created.
- Native async operation cleanup and managed event/timer/request cleanup are
  bounded; no new dependencies were added to the application.

connections, accounts or user preferences were changed by these checks.

## Handoff

Construct `new VPNPageViewModel(new WindowsVpnPageEnvironment(DispatcherQueue))`.
Call `Activate`/`Deactivate` with the page lifetime and `Dispose` on final release.
The page owns a separate cancellation token for its MCP bridge lifetime. Map the
bounded error/status codes through localized resources; do not display native
exception text. Integration owner handles page layout/Narrator/localization and
MCP permission/failure/lifecycle checks. Visual behavior and actual Windows VPN
settings launching remain unverified; no Windows UI automation was used.
